# HCU 算子开发与调优

## 先定口径，算每个形状的访存地板

1. 写明真实调用的输入、输出、dtype、stride、TP 每 rank 形状和计时边界。锁定调用方对布局的约束。若允许离线打包 W，记录打包后的有效大小和复用条件。每次调用都需付出的转换、跨 kernel 中间读写或合并计入相应路径。
2. 在预留的目标卡上按节点已有方式**固定核心与 HBM 两种频率**。记录 GPU/BDF、开放 CU、频率档位和负载下实测 MHz、软件版本、计时方式。扫描中和结束时复核，发生漂移或竞争的区段单独保留并重测。测试结束恢复本次改变的卡状态。
3. 项目建模参考值如下，单位为十进制 TB/s。异构节点、新型号和显著不同的时钟或 CU 配置，用当地定频微基准校准并记录来源。HBM 的两个参考实现、L2 热集测法和 ISA 检查见[带宽校准与指令核对](references/bandwidth-and-isa.md)。

| 架构 | HBM | L2 |
|---|---:|---:|
| gfx936 | 1.5 | 6.0 |
| gfx938 | 2.0 | 6.0 |

**GEMM** 用每 rank 的 `X[M,K] × W[K,N] → Y[M,N]`。下式的 X、W、Y 均为字节数，分别乘各自的元素宽度，INT8 输入、BF16 输出时分别是 1、1、2 B。设 CTA 实际负责的 tile 尺寸为 `tile_m × tile_n`，公式中的 BM、BN 是 **CTA 块数**。

```text
BM = ceil(M / tile_m)                     BN = ceil(N / tile_n)
B_HBM = X + W + Y                         # 两个输入首次读，输出写一次
B_L2  = (BM - 1) × W + (BN - 1) × X       # 同一 W 被其他 M 块再读，同一 X 被其他 N 块再读
floor_us = B_HBM / (BW_HBM × 10⁶) + B_L2 / (BW_L2 × 10⁶)
```

每个 M 用**实际采用的路由和 tile**计算。常规有掩码的尾块按有效字节计。有填充实读、scale、读旧 Y、split-K 中间缓冲时，把字节加到实际经过的层级。对于混合 tile、分块 dispatch，按段枚举 CTA 访问量，再按实际缓存条件归属首次读和重读。同一打包权重因驱逐或换布局再次从 HBM 取时重新计 HBM，热驻留假设要能用实测支撑。该加和公式是约定的访存参照，若测得更快，核对缓存冷热、重叠和字节口径，保留原始点。

**规约与逐元素算子**按每趟 HBM 读写总和除以 HBM 带宽。例：两段规约将 partial 写到显存再读回，分别计一次写和一次读；CTA 内经寄存器、LDS 传递的 partial 只计入片上访存分析。可直接使用[地板计算脚本](scripts/floor.py)。

## 先把访存调好，再加计算

1. 先扫 **M=1–256 的每个整数**。保留正确的参考实现、优化前版本和可用的对比库。令纯访存探针走生产路径的 grid、CTA 次序、lane 地址、尾部 mask、预取、缓存策略和输出写回，去掉矩阵乘、规约或逐元素主体。用最小可观察依赖保住所有目标 load/store，检查它的额外字节和指令。热缓存与冷权重工作集分开测。
2. 逐点记录纯访存延迟 `mem_us` 及距地板的差。先试能改变实际读写的设计，例如 W 转置或预打包、相邻 lane 合并读取、CTA 的 M/N 遍历顺序、向量宽度、预取深度和寄存器轮转。对小 M 同时看 CTA 数能否铺满可用 CU，一个 wave 后是否只余少量尾块。
3. 对落后点及相邻正常点，反汇编**实际加载的代码对象**，核对 global/LDS 指令、预取与首次使用间距、wait、barrier、spill 和尾部分支。固定布局只换调度、或固定调度只换布局，配对复测。若高层实现无法稳定生成所需指令，再比较 HIP C++、内联汇编或手写汇编。对“编译器打断流水”的结论给出 ISA 差异及耗时证据。
4. 在选好的读写路径上分步加回计算和 epilogue，复查 VGPR/LDS、占用率、等待及完整 kernel 延迟。用相同输入与可信参考检查结果、尾块边界和输入输出契约；按该算子的数值契约做逐位或容差比较。只把正确性通过且独立复测有收益的路径加入默认选路。

## 用逐点结果决定下一轮

每个整数 M 对每条要画的实现预热、重复测量，保存原始样本和中位数。用同一设备时间口径，例如同一 stream 的 HIP events，或相同 graph replay 次数归一到一次调用。基线与候选交替或随机顺序复测，保持数据、缓存状态和频率一致。M=1–256 稳定后分段向目标上限扩展，每一段仍覆盖**所有整数**。优先调查下列点。

| 信号 | 判定和下一步 |
|---|---|
| 小 batch 带宽 | **M=1–64 的目标区间为参考带宽的 90%–100%，含两端**。纯 HBM 路径算 `(读B+写B)/(时间×参考带宽)`，单位对齐。混合 HBM/L2 的纯访存路径用 `floor_us/mem_us` 衡量模型达成率，另列两级计数器带宽。完整算子也报告地板/实测比。低于 90% 时排查启动开销、并行度、布局和等待；高于 100% 时保留原值，复核参考带宽、字节数、缓存状态及计时范围。 |
| 小 M 更慢 | 找到 `m1 < m2` 且 `T(m1) > T(m2)` 的点，含非相邻点。配对重跑，试用大 M 的路由处理小 M，核对尾部 mask 及实际少算的工作量。 |
| 整数倍超线性 | 对可沿 M 独立拆分的算子，若 `T(km) > k × T(m)`，例如 2 倍工作量花 2.2 倍时间，实测一次大调用和 k 次小调用。把真实 launch、切片、合并和缓存效应计入同一范围；若拆分胜出，可作为调优对照或回退路由。 |
| 单点毛刺 | 如 `T(63) > max(T(62), T(64))`，将三点在同卡交替重测，检查路由、tile 边界、wave 尾部和 wait。保留原始样本，用复测后的中位数更新曲线。 |

用[逐点诊断脚本](scripts/diagnose_sweep.py)列出候选点、参照 M 和比值。按重复样本的实际波动选 `--noise-pct`，默认列出所有倒挂、倍数超时及毛刺。只有沿 M 切分后语义独立时才加 `--split-independent`。参数、表头和出图示例见[逐点数据与交付](references/sweep.md)。
