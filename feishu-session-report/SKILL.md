# 飞书会话工作汇报

仅在用户主动调用本技能时执行。把当前 Codex 会话截至调用时的相关工作写成一篇可直接用于会议汇报的简报。用户可指定主题、时间范围、读者或目标文档。

## 提取会话事实

- 优先使用当前会话可见的用户要求、实际操作、交付物、实测结果和后续更正。默认覆盖当前会话与工作相关的内容，多项独立工作可分主题。证据不足且能可靠识别当前会话时，用可用的会话读取工具补查当前会话的相关回合。仍无法确认的内容注明边界，不猜测时间、结果或结论。
- 计划、进行中、已完成和已验证按证据表述。只保留影响结论的数字、条件和来源。可链接读者可访问且适合写入目标文档的交付物或证据。省略凭证、个人隐私和与汇报无关的日志或内部细节。

## 组织文稿

标题默认用「YYYY-MM-DD｜任务主题｜工作汇报」。正文先交代时间和任务，再给当前进展与结论，最后简述过程。用自然短句，方便直接口述。

- **时间**：写有依据的工作日期或起止范围，使用用户时区。只能确认汇报日期时标注为「汇报日期」。跨度有依据时可同时注明汇报日期。
- **任务描述**：一两句话说明目标和背景，让没看过会话的同事也能理解。
- **当前进展**：具体说明已交付什么、如何验证、还卡在哪一步。只有确有证据时才写完成比例或验收结果。
- **结论与经验**：给出已验证的结论和适用条件，提炼可复用的做法。尚无定论时写清待验证项。
- **过程简述**：按实际顺序交代关键动作、决策或转折，保留影响结果的排查步骤。

## 数据证据

- 有关键实测数据时，在正文结论旁放原生表格或已有图，展示能支撑结论的数值。对比表标注场景、基线、变更后、单位和变化量，并交代影响可比性的设置。正文选关键档，完整结果随文留存。
- 有压测或实验时，将完整结果表、汇总导出或复核结论必要的原始结果上传为飞书文档附件。飞书中已有完整可访问的结果时，在正文引用该数据文件或表格。标明各附件的配置、覆盖范围以及对应的基线或实验组。优先用会话中已经下载的文件；只有服务器上存在结果时，通过现有访问方式提取相关文件到临时目录并上传。只提取汇报所需的结果，沿用用户指定的传输和共享范围。
- 核对来源、条件、行数和关键值，保留原始精度与失败档。附件写入后回读文档确认文件存在、名称和用途对应，必要时下载核验。缺少完整数据、文件不可访问或上传失败时，在正文和回执里说明已留存内容及缺口。

## 写入与回执

1. 依照 `lark-doc` 和 `lark-shared` 的当前指引操作。使用 lark-cli 时优先读取其内置指引，例如 `lark-cli skills read lark-doc`，以及创建、追加或回读对应的引用文件。默认用飞书用户身份和 DocxXML，正确转义正文中的 XML 特殊字符。
2. 用户要求先预览时，只在会话中提供草稿。用户明确要求写入已有正文时，使用该次指定的目标。默认新建并归档时，先使用用户为本次指定的飞书 Wiki 或 Docx 索引，未指定时读取环境变量 `FEISHU_REPORT_INDEX_URL`。两处都没有配置时，请用户提供索引链接。
3. 默认归档时，在用户自己的飞书云空间新建独立汇报文档。按 `lark-doc` 的媒体指引上传所需附件并验证。回读正文、关键数据和附件后，将「日期｜任务主题｜工作汇报」作为可点击链接追加到已选索引文末。索引只放标题和链接，沿用现有样式。共享权限按用户指示另行处理。
4. 归档后回读索引中新增的条目，核对链接指向新文档。回执提供汇报链接和索引链接，说明已留存的数据范围。若正文已创建而索引追加失败，保留并返回正文链接，只补做索引步骤。写入结果不明确时先按本次标题、链接和附件名查证，避免重复新建或追加。若正文未能写入，提供可直接使用的稿件及失败原因。
