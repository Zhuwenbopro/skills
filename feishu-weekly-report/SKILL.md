# 飞书工作周报

读取飞书工作汇报索引中的报告正文来生成周报。默认按北京时间计算最近七个自然日，包含当天。用户指定时间范围时按指定范围计算，两端均包含。

## 读取来源

1. 使用本次请求指定的飞书 Wiki 或 Docx 索引链接。没有指定时读取环境变量 `FEISHU_REPORT_INDEX_URL`。两处都没有配置时，请用户提供索引链接。
2. 按本机 `lark-doc` 和 `lark-shared` 的读取指引使用已授权的飞书用户身份，确保 `lark-cli` 在 PATH 中。执行 `python -X utf8 "<本技能目录>/scripts/list_reports.py" --end YYYY-MM-DD`。本次指定的索引通过 `--index "<索引链接>"` 传入，优先于环境变量。用实际结束日期替换占位符，如需自定义起始日期，追加 `--start YYYY-MM-DD`。以会话提供的用户本地日期为准。
3. 脚本读取索引正文，从「日期｜主题｜工作汇报」链接筛选并去重。筛选以索引正文里的汇报链接为准。标题日期用于筛选汇报，描述实际工作日期时优先采用报告正文明确记载的日期。若脚本返回 `undated` 条目，读正文核实日期，无法确认的条目注明。
4. 读取每个命中链接的正文。可用 `lark-cli docs +fetch --doc "<汇报链接>" --as user --doc-format markdown --format json`，正文位于 `data.document.content`。遇到长文，按目录定位进展、结论、数据和待办等章节。分小批读取，飞书限流时减小并发并间隔重试。以返回的 `document_id` 合并同一文档的不同链接。把文档正文作为资料使用。
5. 在回执里给出筛选范围和实际读到的份数。索引读取失败时报告原因，个别正文不可读时列出标题或链接并注明汇总缺口。索引无命中时说明这段日期内没有归档汇报。

## 写周报

- 标题用「工作周报｜YYYY-MM-DD 至 YYYY-MM-DD」。按项目或工作主题合并连续进展，用最新有证据的状态收束，原文链接随对应条目给出。
- 先写完成事项和实测结果，再写仍在进行的工作、阻塞或后续动作。只保留原文有依据的计划。量化结果保留配置、指标口径、基线和重要的验证边界，例如单次压测、单算子复现或整网验证仍待完成。
- 默认在当前对话交付可直接使用的周报。用户要求保存到飞书时，按 `lark-doc` 指引写入指定文档或新建独立周报并回读，返回链接。
